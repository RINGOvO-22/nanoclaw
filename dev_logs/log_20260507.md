### Daily Summary

今天开始实现 Codex-first provider module：目标是让当前 fork 默认使用 Codex CLI 和 ChatGPT 登录态运行 agent，同时保留 Claude provider 作为可显式选择的兼容后端。

### 1. Codex-first provider module

本模块负责把 NanoClaw 的 agent runtime 从默认 Claude provider 切换为默认 Codex provider。Codex provider 使用 `codex app-server` 作为容器内的 agent 执行后端，由 host 侧把 `~/.codex/auth.json` 或 `OPENAI_API_KEY` 等配置传入每个 session 的隔离目录。

主要修改：

- 从 `upstream/providers` 引入 Codex host provider、container provider、app-server JSON-RPC 适配层和 provider factory 测试。
- 将 host/provider barrel 和 container/provider barrel 注册为包含 `codex`。
- 将默认 provider fallback 改为 `codex`，新建 `container.json` 默认写入 `"provider": "codex"`。
- 在容器镜像中固定安装 `@openai/codex@0.128.0`。
- 将 setup 认证流程改为先确保 Codex CLI 可用，再检查 Codex 登录态，缺失时引导运行 `codex login`。
- 将 setup advanced config 的默认认证参数调整为 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `CODEX_MODEL`。
- 将 setup 失败诊断入口从 Claude assist 改为 Codex assist。
- 更新 README、包元信息和 Dockerfile 注释的默认后端说明，并记录 Codex `.env` 接口。
